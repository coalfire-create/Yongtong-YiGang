# 프로젝트 브리프 — 페르소나 A 타겟 대응 (중형 입시학원 원장)

**프로젝트명:** 학원 홈페이지 스타터 패키지 — 페르소나 A 대응
**대상:** 원생 100~300명 규모 보습·입시학원 원장, 자체 홈페이지 없음, 블로그로만 홍보 중
**목표:** 4개 부서(기획·마케팅·기술·운영)가 각자 역할에 따라 영업~제작~인도까지 이어지는 전체 패키지를 준비, 실제 영업 착수가 가능한 상태로 완성

## 부서별 업무 분담

| 부서 | 담당 업무 | 산출물 |
|---|---|---|
| 기획·디자인 | 요구사항 정의, 사이트맵, 일정 수립 | `01_planning_PRD.md` |
| 마케팅 | 아웃리치 메시지, SEO/카피, 콘텐츠 캘린더 | `02_marketing_outreach.md` |
| 기술·개발 | 기술 스펙, Supabase 설계, 데모 랜딩페이지 제작 | `03_tech_spec.md`, `04_tech_demo/index.html` |
| 고객지원·운영 | 상담 응대 스크립트, SLA, 최종 검수 체크리스트 | `05_ops_cs_manual.md` |

## 진행 순서 (실전 적용 시)
1. **마케팅**이 아웃리치 메시지로 원장에게 최초 접촉 → 데모 페이지(`04_tech_demo/index.html`) 발송
2. 원장 회신 시 **운영**이 응대 스크립트로 1차 상담 및 견적 안내
3. 계약 성사 시 **기획**이 PRD를 고객 맞춤으로 확정(학원명/커리큘럼/실제 콘텐츠 반영)
4. **기술**이 실제 사이트 개발(데모를 베이스로 커스터마이징) 및 Supabase 연동
5. **운영**이 최종 검수 체크리스트로 QA 후 고객 인도

## 검증 결과
- HTML 데모 페이지 구문 파싱 검증 완료(에러 없음)
- 모든 부서 문서에 페르소나 A의 페인포인트("체계 없어 보인다")·구매 트리거(경쟁 학원 온라인화)가 일관되게 반영됨을 교차 확인
- 데모 페이지는 표준 CSS(Grid/Flexbox)를 사용하므로 실제 브라우저(Chrome/Safari 등)에서 열어야 정상적인 디자인으로 보임 — 이 작업 환경의 렌더링 도구는 구형 HTML 변환기라 레이아웃이 깨져 보일 수 있음
